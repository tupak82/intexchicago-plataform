# Intex Chicago Production Closeout

This document records the final production-readiness pass for the Next.js platform.

## Code gates

- `npm run verify` is the canonical CI command and must pass before merge/deploy.
- TypeScript remains `strict: true`.
- The platform validator remains authoritative for migration, SEO and verified-claim guardrails.

## Roofing differentiation

- Service-page roofing visuals are dispatched to dedicated service modules with separate markup and CSS-module keyframes.
- Roof repair, replacement, hail damage, Chicago ice-dam behavior, TPO/flat roofing, commercial roofing and inspection each have their own visual treatment.
- `ServiceCardAnimation.tsx` is now a dispatcher only and no longer contains a shared generic roof scene.

## Tracking hooks

The code supports environment-driven tracking without committing production IDs:

- `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`
- `NEXT_PUBLIC_GOOGLE_ANALYTICS_ID`
- `NEXT_PUBLIC_GOOGLE_TAG_MANAGER_ID`

The client tracking layer pushes these dataLayer events when applicable:

- `phone_click`
- `email_click`
- `estimate_cta_click`
- `generate_lead` after the estimate flow renders its confirmed-success state

If GTM is configured, direct gtag loading is suppressed to prevent duplicate page tracking; GA4 should then be configured through GTM.

## SEO/canonical host

- `RoofingContractor` schema remains the primary homepage local-business schema.
- Sitemap and robots are generated by Next.js.
- `/admin/` and `/api/` remain disallowed for crawlers.
- `www.intexchicago.com` is permanently redirected to the canonical non-www HTTPS host by Next.js.

## Still environment-dependent before domain cutover

The following cannot be truthfully marked complete from repository code alone:

- Hostinger production MySQL credentials and schema application.
- Real end-to-end lead persistence against production MySQL.
- Approved GA4/GTM/Search Console IDs in Hostinger environment variables.
- Hostinger domain mapping and SSL issuance/verification.
- Final production mobile/desktop/browser QA against the deployed preview.
- Final WordPress filesystem/database backup.
- Full redirect inventory from WordPress export/Search Console beyond already verified redirects.
- Final security/penetration review.

Do not delete the legacy WordPress backup until the production deployment has passed the documented smoke tests and rollback window.
